# 출처 정책 — 복수 출처 교차 확인 기반 영어 학습 콘텐츠

최종 갱신: 2026-10-06

## 1. CATCHY는 뉴스 요약 서비스가 아니다

CATCHY는 특정 기사 한 편을 번역하거나 재가공해서 보여주는 뉴스 요약 서비스가
아닙니다. 여러 공개 출처에서 공통으로 확인되는 사실관계를 바탕으로, CATCHY가
새로 작성한 영어 학습 콘텐츠(제목·요약·표현 예문·퀴즈)를 제공하는 **영어
학습 콘텐츠 서비스**입니다.

이 구분은 단순한 마케팅 문구가 아니라 콘텐츠 생성 규칙 자체에 반영돼
있습니다.

- 기사 본문 전문을 저장하거나 노출하지 않습니다.
- 기사 문장을 그대로 복사하지 않습니다.
- 제목·요약·예문·퀴즈는 모두 CATCHY가 새로 작성한 문장입니다.
- 원문 링크는 "더 읽어보고 싶다면 여기로" 수준의 참고 링크로만 제공합니다.

## 2. 왜 기사 한 편을 재가공하지 않는가

기사 한 편의 문장 흐름이나 관점을 그대로 따라가며 요약하면, 그 결과물은
사실상 해당 기사의 2차 저작물(번역·요약본)에 가까워집니다. 이는 원문
매체가 실제로 그런 번역·요약·재게시를 허락했는지와 별개로, "이 콘텐츠가
특정 기사를 대체하거나 재가공한 것인가"라는 질문에 CATCHY가 "그렇지 않다"고
답할 수 없게 만듭니다.

그래서 CATCHY의 콘텐츠 생성 규칙은 처음부터 "기사 한 편을 입력받아 요약을
출력하는" 구조를 피하고, "여러 출처에서 공통으로 확인되는 사실을 입력받아
독립적인 학습 콘텐츠를 작성하는" 구조를 택합니다.

## 3. 왜 복수 출처를 요구하는가

- 출처가 1개뿐이면, 그 콘텐츠는 결과적으로 해당 출처 하나를 요약한 것과
  구별하기 어렵습니다.
- 출처가 2개 이상이면, 적어도 하나의 사실을 두 군데 이상에서 교차 확인했다는
  의미가 되고, 특정 매체의 관점이나 문장 구조에 종속되지 않은 독립적인
  콘텐츠를 작성할 근거가 생깁니다.
- 이 기준은 `hasEnoughSources(trend)` 함수(`src/lib/trend-validation.ts`)로
  코드에 강제됩니다. `sources.length >= 2`를 만족하지 못하면 해당 트렌드는
  draft 상태에 머물고, `getPublishedTrends()` 결과에 포함되지 않습니다.

## 4. 왜 official/platform 출처를 우선하는가

출처는 신뢰도에 따라 세 단계로 구분합니다.

1. **공식 출처(official)** — 아티스트/소속사 공식 발표, 영화사·스트리밍
   플랫폼 공식 페이지, 시상식·스포츠 리그·기관의 공식 페이지, 공식 차트·
   공식 기록·공식 보도자료. 발표 주체가 자기 자신에 대한 사실을 직접 밝히는
   자료이므로 사실관계 오류나 왜곡의 위험이 가장 낮습니다.
2. **플랫폼/차트성 자료(platform)** — Spotify, YouTube, Netflix, Billboard
   차트 등. 사람이 작성한 해설이 아니라 플랫폼이 직접 관리하는 데이터이므로
   편집자의 관점이 섞여 들어갈 여지가 적습니다.
3. **보조 확인용 매체 기사(media)** — 일반 매체의 기사. 사실관계를
   보조적으로 확인하는 용도로만 쓰고, 문장이나 긴 요약, 이미지는 인용하지
   않습니다.
4. **참고 자료(reference)** — 배경 정보를 확인하기 위한 자료.

`hasOfficialOrPlatformSource(trend)` 함수는 출처 목록에 official 또는
platform 타입이 최소 1개 있는지 확인합니다. 보조 매체 기사만으로 구성된
콘텐츠는 "매체 보도를 따라간 콘텐츠"라는 인상을 줄 수 있으므로, 공식 또는
플랫폼 출처로 한 번 더 사실관계의 기준점을 둡니다.

## 5. 왜 media 출처는 보조 확인용으로만 쓰는가

일반 매체 기사는 유료 라이선스 계약이 필요한 경우가 많고, 재사용 조건이
매체마다 다르며 확인하기 어렵습니다. 그래서 CATCHY는 media 출처의 문장이나
표현을 그대로 가져오지 않고, "이런 사실이 보도된 적이 있다"는 정도의
교차 확인 용도로만 사용합니다. 콘텐츠 본문(제목·요약·예문·퀴즈)은 media
출처의 문장 구조나 관점을 따라가지 않고 CATCHY가 독립적으로 작성합니다.

## 6. 왜 원문 전문·이미지·영상·SNS 캡처·가사·대사를 쓰지 않는가

- 기사 본문 전문을 저장·노출하면 사실상 원문을 재게시하는 것과 다르지
  않습니다.
- 사진, 썸네일, 영상, SNS 캡처, 댓글, 가사, 대사는 텍스트와 별도의
  저작권·초상권·플랫폼 약관 문제를 가지며, 출처가 텍스트 재사용을
  허용한다고 해서 이런 미디어까지 자동으로 허용되는 것이 아닙니다.
- 그래서 CATCHY는 이런 자산을 처음부터 수집·저장·노출 대상에서 제외하고,
  원문 링크는 "참고 출처" 영역의 외부 링크로만 제공합니다. 링크 미리보기,
  OG 이미지, 썸네일도 렌더링하지 않습니다.

## 7. "법적 리스크 0"을 보장하지 않는다

이 문서에 정리된 원칙(복수 출처 교차 확인, official/platform 우선, media
보조 확인용, 원문 전문·이미지·영상 미사용, draft→published 수동 검토)은
법적 리스크를 **낮추기 위한** 장치이지, 법적 리스크를 **0으로 만드는**
장치가 아닙니다. 다음과 같은 경우는 여전히 사람이 판단해야 합니다.

- 공식 출처라도 특정 국가/관할권에서 추가 제한이 있을 수 있습니다.
- 복수 출처가 같은 오보를 공유하고 있을 수 있습니다.
- 표현 예문이나 whyTrending 문구가 특정 인물·단체에 대한 사실 적시로
  읽힐 수 있는 경우, 명예훼손 등 별도 법적 쟁점이 생길 수 있습니다.

그래서 코드/문서 어디에도 "완전 안전", "법적 리스크 없음" 같은 표현을
쓰지 않습니다.

## 8. 운영자 게시 전 체크리스트

트렌드의 `status`를 `draft`에서 `published`로 바꾸기 전에 아래를 확인합니다.

1. `sources.length >= 2`인가. (`hasEnoughSources`)
2. 출처 중 `sourceType`이 `official` 또는 `platform`인 항목이 최소 1개
   있는가. (`hasOfficialOrPlatformSource`)
3. 각 출처의 `originalUrl`이 실제로 존재하고 접근 가능한 실제 URL인가.
   확신할 수 없는 URL을 추측해서 만들지 않았는가. (확신할 수 없다면
   `usageNote`에 `"demo source placeholder"`라고 명시하고 해당 트렌드는
   draft로 유지합니다.)
4. `title`, `summary`, `englishSummary`, `koreanSummary`, `whyTrending`,
   `expressions[].exampleEn/exampleKo`가 모두 CATCHY가 새로 쓴 문장이고,
   특정 출처의 문장을 그대로 베끼거나 문장 구조만 바꾼 것이 아닌가.
5. 기사 본문 전문, 이미지, 영상, SNS 캡처, 댓글, 가사, 대사 관련 필드를
   포함하지 않았는가.
6. `reviewedAt`을 실제 검토 시점으로 기록했는가.
7. `isPublishableTrend(trend)`가 `true`를 반환하는가. (위 1~2번을 코드로
   다시 확인하는 최종 게이트)

이 체크리스트를 통과하지 못한 콘텐츠는 `status: "draft"`로 유지하고,
`getPublishedTrends()` — 그리고 그 결과만 사용하는 홈 화면과 퀴즈 —
에는 노출하지 않습니다.
